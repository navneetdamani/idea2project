# Daily Practice

Buildless, browser-local learning app at `/applications/daily-practice/`. Run `node tests/daily-practice.cjs` from the repository root. No account, backend, external AI service, or new dependency is required.

SAT defaults to 365 days and 34 introductory micro-topics spanning the eight official content domains. RD defaults to 90 days and 58 micro-topics grouped according to the target completion year (2022–2026 or 2027–2031). The underlying introductory lesson pool is shared; this is a habit-building supplement, not exhaustive coverage of every item in CDR’s expanded outline, a complete SAT question bank, or an exam-readiness assessment. Original examples and questions have not undergone independent educator or dietitian review. Sources: https://satsuite.collegeboard.org/practice/content-domains and https://www.cdrnet.org/study (checked November 13, 2026).

Every core topic is introduced once before review cycles begin. Review priority combines elapsed daily sessions and the earlier daily accuracy for a topic, excluding the immediately preceding topic when possible. Completed-session count advances the sequence, so missed days never skip content. The full session sequence, next five topics, completed-topic count, question count, and per-topic checked results are visible. This tracks topic coverage, not mastery. RD plans retain their selected outline; an older-outline plan slipping into 2027 displays a warning.

The November 23 update replaces fixed question slicing with `questions.js` and `question-cases.js`. Quantitative templates calculate answers and plausible distractors from changing values; reading templates include their complete passages, tables, or notes. RD topics have additional applied cases. Question IDs hash the normalized prompt, so changing option order or distractors never makes an old prompt count as fresh. No remote question service, AI API, or credential is used. Clinical cases remain introductory educational examples requiring independent content review before claims of comprehensive exam readiness.

Generated topics serve up to three unseen questions per quiz; finite case banks serve two. New quiz content and selected answers are persisted when shown; feedback and checked results survive reloads. The learner can resume a saved quiz, including its original questions and choices. Extra practice is available after daily completion, with separate answer history and no extra streak credit. Finite custom/case banks show an exhaustion notice rather than silently recycling content; repeating used questions requires an explicit review action and is labeled. Extra practice can exhaust a topic's bank before its later daily review; the same explicit exhaustion behavior applies. Unsubmitted abandoned questions remain marked shown.

Existing v1 plans are migrated in place: historical topics are derived from the original scheduling algorithm, completion dates/scores are retained, and the two former fixed prompts for completed topics are marked seen. Newly scheduled sessions introduce uncompleted topics first. Backup restore accepts both old and new plans; new backups include question history and resumable quizzes.

A completed learning cycle requires a reading confirmation, all quiz answers, feedback display, and an explanation-review confirmation. Accuracy records the first submitted attempt; an incorrect answer does not prevent completion. The missed-activities panel lists unfinished scheduled slots earlier than today, with original dates. The learner completes the earliest unfinished slot in order and may catch up multiple overdue activities on one day, then complete today's slot. Future scheduled activities cannot be completed early; extra practice remains available. Each activity retains its original `scheduledDate` and actual completion `date`, plus `kind` (`daily` or `catchup`). Completion history is nondecreasing by actual date and remains a contiguous sequence of unique indices.

Streaks count unique actual study dates, so catching up three past activities today earns one study day and never fabricates completion on missed dates. The current streak includes yesterday until today is missed. Each catch-up is another 10–15 minute activity, not a promise that the entire backlog fits into one session. At one activity per day the estimated finish moves with progress; catch-ups can bring it forward. Date arithmetic uses UTC ordinals and local noon construction to avoid daylight-saving length errors. The device date is trusted; there is no server enforcement or tamper resistance.

Named plans are browser-local convenience profiles, not authenticated accounts. Data remains under `idea2proj.daily-practice.v1` in localStorage and is visible to anyone using the browser. Storage failures show a session-only warning. Backup export includes all plans; restore validates the schema and merges new IDs without replacing existing plans. Restoring an already-present plan keeps its existing local history. Multi-tab completion checks reconcile a changed store before writing, but localStorage does not provide atomic cross-tab transactions.

Custom topics require a supplied JSON syllabus with `topics`, each containing `domain`, `title`, `lesson`, `example`, and 2–100 `questions`. Questions have `prompt`, 2–4 distinct `options`, zero-based `answer`, and `explanation`. A sample file is downloadable in setup. Custom durations must allow at least one session per topic; extra days are reviews. No exam-name-only syllabus generation is claimed. Built-in generators are used only by the preset courses; imported content uses its own bank. API keys must never be embedded in static files.

Checks: `node tests/daily-practice.cjs` simulates complete 365-day SAT and 90-day RD sequences with different seeds and score patterns, checks unseen prompts, validates generated question schemas and calculated/shuffled answer keys, and covers migration, date boundaries, streaks, overdue slots, and exhaustion. `node tests/daily-practice-ui.cjs` covers saved answers/feedback, duplicate grading prevention, extra-practice separation, old progress, escaping, stale-tab reconciliation, multiple same-day catch-ups, today's activity after catch-up, future-day gating, and truthful streak dates. Both run in the existing Site checks workflow.
